# tablelog. — 테이블로그

친구들과 함께 쓰는 보드게임 리더보드. Next.js App Router + TypeScript + MongoDB로 구현한 Vercel 배포용 프로젝트입니다.

## 시작하기

Node.js 20.9 이상을 사용하세요.

```bash
npm ci
npm run dev
```

http://localhost:3000 에서 열립니다. MongoDB 설정이 없으면 **데모 모드**로 실행됩니다. 데모의 샘플 기록과 변경 사항은 해당 브라우저의 localStorage에만 저장되며 다른 사용자와 공유되지 않습니다. 데이터베이스 연결 실패를 데모 모드로 숨기지 않고 오류를 표시합니다.

## Vercel 배포

1. 이 폴더를 GitHub 저장소에 올립니다. `.env.local` 등 비밀 정보는 커밋하지 마세요.
2. MongoDB Atlas에 클러스터와 읽기/쓰기 권한이 있는 DB 사용자를 생성합니다. Atlas의 네트워크 접근 설정에서 배포 서버의 접속을 허용하세요. 고정 egress IP가 없는 환경에서는 Atlas/Vercel 네트워킹 옵션을 확인하세요.
3. Vercel에서 저장소를 Import하고 프레임워크를 **Next.js**로 선택합니다. 별도 빌드/출력 설정은 필요 없습니다. 프로젝트를 하위 폴더에 넣었다면 Root Directory를 이 폴더로 지정하세요.
4. Vercel 환경변수를 설정합니다.

| 변수 | 용도 |
|---|---|
| `MONGODB_URI` | Atlas 연결 문자열. 비밀번호의 특수문자는 URL 인코딩 필요 |
| `MONGODB_DB` | DB 이름. 기본값 `tablelog` |
| `BGG_API_TOKEN` | 선택 사항. BGG 전체 게임 검색용 서버 토큰 |

5. Deploy합니다. 환경변수를 변경했다면 Redeploy합니다.
6. 새 DB는 빈 테이블로 시작합니다. 게임과 플레이어를 추가하고 첫 기록을 남기세요. 샘플 데이터는 실제 DB에 자동 삽입되지 않습니다.

로컬에서 DB에 연결할 때는 `.env.example`을 `.env.local`로 복사하고 값을 입력하세요. 토큰과 DB 연결 문자열은 서버에서만 읽습니다.

## 기능과 계산 기준

화면은 스코어보드와 플레이어 통계 두 탭으로 구성됩니다. 소개 문구와 장식 영역 없이 게임/플레이어 선택과 통계 표를 바로 표시합니다. BGG 검색과 직접 게임 등록, 이름으로 플레이어 등록을 제공합니다. 테라포밍 마스·도미니언·글룸헤이븐: 사자의 턱이 기본 검색 목록의 맨 앞에 있습니다. 실제 DB에는 게임이나 샘플 기록을 자동 삽입하지 않습니다.

- 점수: 게임별 개인 최고 점수와 평균 점수
- 판수: 해당 게임의 전체 판수와 개인 참가 판수
- 등수: 개인 최고 점수 기준 순위, 매 판의 평균 등수, 등수별 판수
- 시간: 모든 게임에서 실제 플레이 시간을 분 단위로 선택 입력. 누적 시간·평균 시간·입력한 판수 표시
- 기록: 게임, 날짜, 참가자, 점수(경쟁형), 시간 입력. 기록 수정 및 삭제 가능
- 협력형: 점수와 순위 없이 참가자별 판수·시간과 시나리오·성공/실패/중단 결과 기록

높은 점수 또는 낮은 점수를 좋은 기록으로 설정할 수 있습니다. 동점은 공동 등수이며 다음 등수는 건너뜁니다(1, 1, 3). 게임별 리더보드도 최고 점수가 같으면 공동 순위입니다. 평균 점수와 평균 등수는 소수점 한 자리로 표시합니다. 참가하지 않은 판은 개인 통계에서 제외합니다. 서로 다른 게임의 점수는 합산하지 않습니다.

승률, 승수 순위, 월별 차트, 메모 입력은 제공하지 않습니다. 게임 검색 결과에는 식별용 일러스트를 사용합니다. 플레이어 색상은 자동 지정됩니다.

로그인 없는 공개 편집 방식으로 누구나 플레이 기록을 추가·수정·삭제할 수 있습니다. 동시 수정 시 버전 검사로 다른 사용자의 최신 기록을 덮어쓰지 않습니다. 다른 사용자의 기록은 새로고침하면 반영됩니다.

## 기존 데이터 호환

기존 MongoDB와 데모 기록을 계속 읽을 수 있습니다. 이전 기록의 시간은 다시 표시하며, 시간을 입력하지 않았던 기록도 그대로 유효합니다. 기존 메모는 화면에 표시하지 않지만 수정 시 보존합니다. 데이터 마이그레이션은 필요 없습니다.

## 시간과 협력 게임

시간은 1~10,000분 사이의 정수로 입력합니다. 모르면 비워 둘 수 있습니다. 미기록 시간은 합계와 평균에서 제외하며, 누적 시간에 참가자 수를 곱하지 않습니다. 협력형 참가자별 시간은 해당 사람이 참여한 판의 입력된 시간만 합산합니다.

사자의 턱은 기본적으로 협력형입니다. 시나리오 번호 또는 이름과 결과는 선택 사항이며, 실패·중단·같은 시나리오 재도전도 각각 한 판입니다. 시나리오 완료율이나 캠페인 진행도를 추정하지 않습니다. 시나리오 내용은 포함하지 않아 스포일러가 없습니다. 시간·시나리오를 포함한 기록은 나중에 수정할 수 있습니다.

기록 방식은 게임 등록 시 높은 점수 / 낮은 점수 / 협력형 중 선택하며 등록 후 고정됩니다. 서버에서도 게임의 기록 방식에 따라 점수 필수 여부를 검증합니다. 협력형은 점수 없이 참가자 ID를 저장하고, 경쟁형에는 시나리오/협력 결과를 저장하지 않습니다.

기본 게임 정보 출처: [테라포밍 마스](https://boardgamegeek.com/boardgame/167791/terraforming-mars), [도미니언](https://boardgamegeek.com/boardgame/36218/dominion), [사자의 턱](https://boardgamegeek.com/boardgame/291457/gloomhaven-jaws-lion).

## 플레이어 통계

플레이어 통계 탭에서 이름을 선택하거나 스코어보드에서 플레이어 이름을 누르면 해당 플레이어의 통계를 볼 수 있습니다.

- 전체: 참가 판수, 플레이한 게임 수, 누적·평균 시간과 시간 입력 판수
- 게임별: 판수, 최고·평균 점수, 해당 게임 스코어보드 순위, 평균 등수·등수별 판수, 누적 시간
- 최근 10판: 게임, 날짜, 본인 점수·등수 또는 협력 시나리오·결과, 시간

서로 다른 게임의 점수와 등수는 합산하지 않습니다. 협력형 게임의 점수·등수는 해당 없음으로 표시합니다. 게임 이름을 누르면 해당 게임의 스코어보드로 이동하고, 최근 기록에서 수정할 수 있습니다.

### 플레이 타이머
- 게임과 참가자 선택 → 시작 → 일시정지/계속 → 종료 → 기록 저장. 시간은 분 단위로 올림하며 저장 전 수정할 수 있습니다.
- MongoDB의 `timers` 컬렉션에서 공용 타이머 하나를 공유합니다. 약 3초 간격으로 동기화하며 서버 시각을 사용합니다.
- 새로고침하거나 화면이 잠겨도 경과 시간이 유지됩니다. 종료 후 기록 창을 닫아도 기록 대기 상태로 남습니다.
- 데모는 현재 브라우저에만 저장됩니다. 여러 기기에서 공유하려면 MongoDB 연결이 필요합니다.

타이머 미사용 시 반복 요청과 화면 갱신은 실행하지 않습니다. 최초 접속 및 타이머 버튼 클릭 시 상태를 확인합니다. 실행·일시정지 상태에서만 3초마다 동기화하며 숨겨진 탭에서는 중단합니다. 종료 후에는 동기화를 멈춥니다. 다른 기기에서 새로 시작한 타이머는 타이머 버튼을 누르거나 새로고침하면 확인할 수 있습니다.
